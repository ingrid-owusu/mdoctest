mdoctest

doctest for Markdown — test the code examples in your README, in any language.

View on GitHub Install from PyPI

Every README ships with commands and code in it. They rot silently — a flag changes, an output format changes, an example starts throwing — and the first thing a new user does is copy your example and hit something broken. Your docs are untested code.

mdoctest runs the console sessions and fenced code blocks in your Markdown and checks that their output still matches what you documented. When something drifts, --fix rewrites the expected output for you.

pip install mdoctest
mdoctest README.md        # check every example still produces its documented output
mdoctest --fix README.md  # rewrite drifted output in place

What it does

  • Any language. Shell/console sessions run in a persistent shell (so cd and environment variables carry across lines). Python >>> doctests run natively. Anything else runs via <!-- mdoctest: run cmd="go run" ext=.go --> — any toolchain you already have.
  • Auto-fix. --fix regenerates the expected output in place and leaves your prose untouched — no more hand-editing transcripts.
  • ... wildcards. Match timestamps, paths, and other noisy output without brittle exact strings.
  • Invisible fixtures. A hidden <!-- mdoctest: setup --> block seeds files an example assumes exist — in a throwaway sandbox that never touches your working tree.
  • Ships where your CI lives. Use it as a pre-commit hook or a GitHub Action with inline PR annotations on the exact block that drifted.
  • Zero dependencies. Pure Python standard library, one install, Python 3.8+.

A 20-second example

Say your README claims:

```console
$ echo hello | tr a-z A-Z
HELXO
```

Run mdoctest README.md and it fails with a unified diff (-HELXO documented / +HELLO actual). Run mdoctest --fix README.md and the block becomes correct. Your documentation can no longer silently lie.
